# Keycloak group bootstrap — local v0.1.6 acceptance

PRD: [sanitized confirmed requirements](prd/PRD-006-keycloak-user-group-role-bootstrap.md). Contract: [runtime and deployment initialization](keycloak-bootstrap-runtime-contract.md).

Authoritative assignments: Chris → `logai_admin` → `logai-admin`; Elvis, Beau and Sunil → `as_lead` → `as-lead`. Same mapping in Build, Release, Client Local, UAT and Production; future usernames/memberships are configuration-driven.

Fresh PostgreSQL/Keycloak import and idempotent bootstrap passed without manual realm repair. All four users were created without invented personal details, required first-login password changes, and received canonical roles through group inheritance, without direct human role assignments. Browser login/callback/business API calls/logout passed. Chris passed `/api/v1/admin/identity`; AS Leads received 403 there. The initial credential failed after password changes. Bootstrap was rerun and all four chosen private passwords still authenticated, with original group/role membership preserved. Missing/malformed API tokens, disabled users and failed UI runtime config were rejected.

See [initial browser acceptance](evidence/keycloak-groups-v0.1.6-local/browser-auth.json), [post-bootstrap-rerun acceptance](evidence/keycloak-groups-v0.1.6-local/browser-auth-rerun.json), [tested image IDs](evidence/keycloak-groups-v0.1.6-local/tested-images.json), [compiled API tests](evidence/keycloak-groups-v0.1.6-local/api-tests.log), [configuration checks](evidence/keycloak-groups-v0.1.6-local/configuration-checks.txt), and [client archive validation](evidence/keycloak-groups-v0.1.6-local/client-archive-check.txt).

17 compiled LogAI API tests passed. All three image archives passed every-layer source/credential scanning and numeric UID checks; final Trivy results contain zero fixable HIGH/CRITICAL findings against the cached database. Refreshed CycloneDX SBOMs are retained alongside each component’s reports. UID 10001 APIs and UID 1000 production UI were tested read-only with explicit writable tmpfs. URL generation and environment isolation passed for all five deployment stages. Workflow and whitespace checks passed.

Validation used disposable users, randomly generated runtime credentials and isolated containers, not the persistent client-local users. It proves behavior without storing the approved shared credential in fixtures or evidence. Live provisioning requires the runtime initial-user secret plus a valid administrative runtime secret. Existing passwords are never reset by deployment initialization; explicit administrative reset remains separate.

No Schneider-owned Helm/Argo resources or service topology were changed. No image publication, signing or registry fresh-pull claim is made. Local application tags remain v0.1.6. Identity API code/image is unchanged from the already-tested v0.1.6 candidate; LogAI API and UI were rebuilt for this PRD.

Release enforcement: five standard-library bootstrap regression tests now run on every platform PR and release, including password preservation, disabled-account preservation, mapping repair and configuration-driven future users. Platform releases additionally run the real clean-Keycloak browser suite against the referenced application images before packaging/publication; failure blocks the release. This CI gate is configured and linted locally, but has not been run remotely or published. Component images must be available in the registry before the platform release gate can run.

Packaging follow-up: runtime `*.env` files, `.env` variants and Windows Zone.Identifier metadata are excluded from source directory copies and rejected by final bundle validation. This prevents operator credentials in a local `compose.env` from entering the archive while retaining `compose.env.example` templates. Negative policy tests cover both runtime env and metadata leaks.

Follow-up validation: all five bootstrap regression tests and the end-to-end release packaging policy suite passed. The shell packager was exercised with a temporary Python ZIP writer because native `zip` is absent locally; its archive extraction, runtime-file filtering and credential/source gates passed. Native ZIP execution remains part of CI. Logs: [bootstrap regressions](evidence/keycloak-groups-v0.1.6-local/bootstrap-regression-tests.log) and [packaging regressions](evidence/keycloak-groups-v0.1.6-local/packaging-regression-tests.log). No API/UI code changes or image rebuilds were required for this follow-up.
